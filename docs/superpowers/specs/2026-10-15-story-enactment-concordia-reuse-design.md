# 故事演绎修正设计：恢复 Concordia 行动裁决与重复干预

日期：2026-10-15。
状态：设计草案；本次只写文档，尚未实施。

后续修订（2026-10-16）：真实模型 run3 暴露最终双字段生成的冗余遗漏。
参见 [正式事件组装与评审修复设计](2026-10-16-story-enactment-canonical-review-design.md)。
该设计修订本文 §6 的最终生成契约、组装与评审顺序及 §11 对应测试要求；
其余核心复用、行动授权、预算和 checkpoint 边界继续有效。

本设计承接 [Phase 1 设计](2026-10-13-story-enactment-phase1-design.md) 和
[第一轮修复方案](../plans/2026-10-15-story-enactment-live-fixes.md)，依据
`gemini-3.8-flash-high_run2`、`gpt-6-luna_run2` 的真实运行复审提出。
实施时采用本文的新契约；未经采用前，原有实现及其结果不变。

## 1. 修正结论与范围

行动结果裁决、保护其他角色自主权、识别重复并推动剧情，Concordia 均有
现成能力。当前问题主要在 story 示例的组合方式和限制：

1. 角色被要求只输出对白，没有独立行动意图；story GM 未接入正常行动
   结果处理，语义复核又禁止旁白描述玩家主动行动，合法行动也无法兑现。
2. 自定义导演只在张力偏离区间时干预，未接入 Concordia 的重复检测。
   故事可以一直重复、评分一直合格，最终超时。
3. 角色可能用“我已经录像”“柜子已经封好”等对白补出未经裁决的事实。
   将对白原样保留，只能证明角色说过这些话，不能证明这些事已经发生。

因此，优先复用 Concordia 的裁决与干预步骤，扩展故事层的输入契约和
适配边界。保留节拍、角色底线、信息隔离、双轨输出、预算与 checkpoint。
不新增另一套执行引擎、物理系统或通用剧情规划器，不修改核心引擎或 typing。

本文明确调整旧设计“非言语行动不在 Phase 1 范围”的限制，引入最小的
自身行动意图字段。仅修改提示、增加轮数或放宽输出校验不能替代此调整。

## 2. 已有能力与复用边界

以下路径均相对于仓库根目录；链接为当前源码位置。

| 已有能力 | 当前实现 | 本方案用法 |
|---|---|---|
| 行动请求与裁决流水线 | [EventResolution](../../../concordia/components/game_master/event_resolution.py) 与 run_chain_of_thought | 保留现有引擎和生命周期，组合裁决步骤 |
| 行动后果判断 | 同模块 attempt_to_result / attempt_to_most_likely_outcome | 首版复用 attempt_to_result，简单行动不增加多候选推演 |
| 其他玩家自主权 | 同模块 AccountForAgencyOfOthers | 参考并保留其边界；是否直接接入见下文 |
| 重复检测与剧情推动 | 同模块 maybe_inject_narrative_push | 在受约束的适配步骤中直接调用，不另写通用重复检测器 |
| 现成组合示例 | [generic GM](../../../concordia/prefabs/game_master/generic.py)、[situated GM](../../../concordia/prefabs/game_master/situated.py) | 复用其组合方式，保留 story 专用收口步骤 |
| 行动与场景组合 | [physically_situated_and_dramaturgic](../../../concordia/prefabs/game_master/physically_situated_and_dramaturgic.py) | 作为参考；本次无需整体切换到时空模拟 prefab |

不能原样接入全部步骤：

- `AccountForAgencyOfOthers` 会对被牵涉的其他实体调用 `act(Yes/No)`。
  这会增加角色调用和日志状态变化；若采用，必须单独验证生命周期、
  预算和角色记忆。首版采用“只裁决当前角色明确提出的自身行动，其他
  角色的新选择留到自己的回合”，配合现有提交前复核，无需增加代答调用。
  不复制该组件另写一份同类实现。
- `maybe_inject_narrative_push` 包含重复判断、五个建议、随机选择和融合，
  并非一个纯布尔检测函数。必须约束上下文和输出并计入预算，不能假装
  它只增加一次调用，也不能绕过环境白名单和最终复核。
- `result_to_who_what_where` 等重写步骤不保证任意字符逐字保真。本方案
  仍由程序使用原始 speech 和获准旁白构造正式事件，不用它们重新生成对白。

## 3. 角色输出契约

复用 `ActionSpec(FREE)` 请求严格 JSON，不新增核心输出类型：

```json
{
  "speech": "我现在核对原件上的日期，之后再讨论效力。",
  "action_intent": "拿起我保管的遗嘱原件，查看落款日期，并向在场人出示该页。"
}
```

两个字段均为字符串；无对白或无行动时使用空字符串，不能同时为空。
`speech` 不含角色标签、旁白或推理；`action_intent` 仅描述当前角色现在
尝试的动作，不预写成功结果、物件新内容、其他角色的决定或过去已完成动作。

示例：

| 输入 | 解释 |
|---|---|
| speech：“请陈母把钥匙拿出来。”，action_intent 为空 | 一次请求；不意味着陈母交出钥匙 |
| action_intent：“用我手上的钥匙尝试开柜。” | 当前角色的尝试；能否打开由 GM 根据既有条件裁决 |
| action_intent：“让陈母认罪并签字。” | 不具有替他人选择的授权；不得生成认罪与签字结果 |
| speech：“我同意暂缓卖宅。” | 当前角色通过言语表达同意；不能推导其他人同意 |
| speech：“我已经拍好了视频。”，action_intent 为空 | 过去行动的自述；无已有记录时不得自动生成视频物证 |

建立一个 contrib 层共享编解码模块供 director、裁决步骤和示例采集调用。
剥离引擎添加的一次角色前缀后严格解析，拒绝额外字段、重复键和错误类型。
解析不得规范化字段内部的原始对白空白，不用 LLM 从混合正文猜测动作。
无效输入走明确 error 路径，不广播、不提交，不循环补问。

原始 action JSON、解码后的 speech 和 action_intent 在本轮暂态中分开保存。
后续步骤不能把整个 JSON 当作对白，也不能将 action_intent 直接算已发生事件。

## 4. 自身行动与其他角色选择的边界

新规则为：角色自主提出自身行动，GM 判断可行性并描述实际结果；GM
不得自行增加当前角色没有提出的行动，或替其他角色产生新的主动选择。

因此必须修改当前复核规则“旁白不得描述任何玩家主动行动”：

- 允许记录当前角色已明确提出、且通过可行性裁决的自身行动及结果。
- 不允许把“请你开柜”改为别人开柜，不允许由一人的发言生成集体同意。
- 失败也产生明确结果，例如“钥匙能够插入，但还需另一把钥匙，柜门未开”。
  不能将失败降级为“他打算以后核验”，又回到重复承诺。
- 其他角色的配合必须有其自身已提交的明确选择依据；不从沉默、表情、
  关系好坏或导演目标推断同意。未经对方选择，本轮可以保持行动受阻。
- 保留角色硬底线。主动行动字段不能成为认罪、泄密或伪造证据的绕行通道。

玩家对白可以是猜测、指控、否认或策略性说辞；它们继续作为有归属的陈述
传播，不作为客观事实。是否符合角色底线也由复核判断；判断不确定不应
自动升级为确证事实。模型语义判断仍需人工评审，不能声称为形式化保证。

## 5. 证据与世界事实

GM 裁决读到什么，必须有故事配置或已发生事件作为依据。首次实现复用
现有 `world_facts`、`gm_only_facts`、`immutable_facts`，由作者补齐关键
文书日期、证据内容、保管位置、开启条件，不新增证据数据库。

信息公开需要合法访问路径。例如：

1. 作者在 GM 专属事实中给出旧遗嘱的日期、封印情况及文本。
2. 律师自主提出检查自己保管的原件。
3. GM 裁决检查是否可行，并记录查看或出示得到的事实。
4. 只有在场可见或明确读出的内容，才能进入公开事件和其他角色观察。

私藏录音的存在不能因为 GM 知道就直接公开。若角色底线禁止披露客户
保密事项，也不能为了完成节拍强迫其播放。邮差送信是允许的环境事件，
并不自动授权 GM 替玩家拆信或编造信的证明力。

剧情关键的物证内容在配置中未定义时，不临时编出能定案的内容；可以
裁决为“现有材料不足以确认”，并保持后续协商或其他结局的可能性。

## 6. 裁决链装配

保持 `EventResolution` 和现有三参数 thought-step 接口，建议顺序为：

```text
读取并严格解析当前角色 action JSON
  → 构造“对白 / 自身行动尝试 / 已知条件”裁决上下文
  → 有行动时调用核心 attempt_to_result；仅对白时跳过行动裁决
  → 融合既有 pending 导演指令，或进行受约束的重复干预（至多一路）
  → 模型生成单字段 stage_directions（严格 JSON，无对白副本）
  → 程序在评审前组装 canonical event；独立评审该待发布事件与来源证据
  → 获准后原样提交 → 广播、剧情后处理、StoryTurn 与 checkpoint
```

（2026-10-16 回填：末端契约原为「生成双轨输出草稿 → 独立语义复核 →
程序构造 canonical event」，已按 [正式事件组装与评审修复设计]
(2026-10-16-story-enactment-canonical-review-design.md) §4–§5 修订为
单字段生成与评审前组装；该设计是本次契约变更的权威表述。）

核心行动结果是候选结果，不因核心步骤已经生成就免于复核。复核检查
自身行动授权、实际结果、他人自主权、私隐和证据来源（原「双轨一致性」
检查随双字段草稿一起取消：评审对象改为程序组装的正式事件，组装本身
不构成语义获准）。复核输入必须显式包含原始 speech、action_intent、
当前角色、初始公开事实、已提交历史、程序组装的 canonical event 和
GM 约束；不能只凭候选旁白推断授权。

行动意图不直接加入 canonical event 充当已完成动作；成功、失败或受阻
的实际结果进入 stage_directions，再由同一字符串进入正式事件与剧本。
无对白时不要生成空的角色对白行；纯动作应能以 Action 段落合法导出。

（2026-10-16 回填：模型不再生成对白副本，「草稿对白空白容差与词句
改写检查」随之取消；原始对白由程序逐字进入正式事件，保真由构造
保证。）

## 7. 重复检测与导演触发

### 7.1 复用方式

增加一个轻量的 contrib thought-step 适配器，内部直接调用核心
`maybe_inject_narrative_push`。仅在 RESOLVE 阶段执行，处理当前候选事件；
不得用它回写已经提交的历史，也不把其返回值直接当作下一轮的命令。

适配器使用同一个预算包装模型创建独立 InteractiveDocument，显式提供：

- 按顺序的近期已提交公开事件；重复判断只能以这些事件为证据。
- 本轮候选结果，明确标为尚未提交，不能当作已发生历史。
- 玩家名单、不可变事实、角色底线与信息边界。
- 可用的环境/NPC 手段，以及不得重复已发生的一次性事件的约束。

返回候选事件继续经过最终复核。不得将未来节拍、允许结局或隐藏真相
当作已经发生的事实。空响应不能静默吞掉本轮角色对白或合法行动。

### 7.2 与张力导演协调

- 保留张力评分及原有 pending 指令流水线。
- 当前已有 pending 张力指令时，只执行该指令，本轮不再调用重复干预。
- 没有 pending 指令、反馈开启、冷却结束、故事尚在运行且到达检查间隔
  时，可以调用重复干预；不要求张力偏离目标区间。
- 默认重复检查间隔为 3 个剧情步、共用现有 3 步执行冷却；属于待真实
  模型验证的工程默认值，不是经验证的心理学或叙事规律。
- 一个回合至多成功融入一次外部干预；两条路径共用执行轮次与冷却记录。
  最终输出获准前只保留暂态候选，拒绝或中断不能消费干预。
- 重复干预在当前回合裁决前执行，依据此前已提交状态。本轮若随后完成
  节拍，不能再在后处理依旧节拍生成新指令；候选干预也不能改写历史。
- 保留重复“检查”与实际“改变事件”的区别：核心 helper 原样返回时只
  记录已检查，不记成功执行，不进入执行冷却。

新的干预原因记为 `repetition`，原张力偏离原因记为 `tension`。
诊断记录检查轮次、原因、尝试/执行状态和执行轮次，不能广播诊断内容。

### 7.3 核心 helper 的限制

该 helper 在重复时会生成多个候选并使用随机选择，提示约束不能保证每个
候选都合法。本次不修改核心函数或伪装成确定性选择：保留候选及最终事件
的归档，最终复核拒绝时沿用明确 error 路径，不无限重抽。
已提交事件回放必须确定；恢复后的真实模型续写不承诺逐字相同。

若真实试验发现该 helper 的白名单违规率过高，再单独提出将“重复判断”
拆为可复用小步骤的核心重构方案。本次不为绕开现有接口写自定义模型代理，
也不一边调用核心 helper、一边另外运行重复检测和另一轮事件生成。

## 8. 模式、预算和生命周期

现有模式名称保留，输入形式增加显式配置 `action_mode`：

- `speech_only`：兼容旧配置，行动意图为空，不从对白倒推过去行动已执行。
- `speech_and_action`：采用本文 JSON 契约；新实验显式选择并归档。

`beats_only` 不开启反馈；`tension_observe` 只记录张力，不开启两类干预；
`director`、`character_depth` 可启用重复干预，并归档具体开关和间隔。
动作契约与反馈开关独立，以便比较只有行动修正和额外导演干预的效果。

所有调用继续经过共享 BudgetGuard 与既有重试包装器：

- 自身行动结果处理通常增加一次 text 调用；纯对白跳过此调用。
- 重复 helper 通常包含一次 choice 判断；判为重复后另有建议、融合调用。
  以实际尝试计费，不按“一个 thought-step 等于一次调用”估算。
- 独立语义复核继续计入预算，不能为节省预算跳过关键校验。
- 解析、行动裁决、重复干预、最终生成或复核期间耗尽预算，均属于提交前
  停止，不提交本步；完成判断或评分期间耗尽沿用原提交后停止路径。

一个已裁决行动仍计为一个 story_turn；读 JSON、角色思考、重复判断、
张力评分和其他管理查询都不增加剧情步数。维持 StoryTurn 先写、checkpoint
后提交的既有边界，不另建行动提交账本。

## 9. 记录、导出和恢复

新运行配置与 StoryTurn 增加显式 schema 版本。新增记录字段：

| 字段 | 用途 |
|---|---|
| raw_action | 引擎角色前缀剥离后的原始 JSON，供审阅与一致性检查 |
| speech | 解码后原始对白，保持所有字面空白与换行 |
| action_intent | 本轮行动请求，供诊断；不能当成已执行结果 |
| stage_directions | 实际行动结果和获准环境/NPC 事件 |
| director_diagnostics | 扩展重复干预原因、检查与执行状态；保持 archive-only |

collector 比较 `StepData.action` 与 raw_action，不再把整个动作 JSON 与
speech 比较。FDX、Fountain、纯文本仍只用 speech 和 stage_directions
渲染，不能把 JSON 或未执行意图写进对白或旁白。

旧记录按 speech_only 读取，补空 action_intent，不改写旧对白、旁白和
已提交事实。恢复旧运行时保持原动作模式，不能中途切换契约；新动作模式
使用新目录。旧 checkpoint 缺少重复检测状态时采用“未检查/未执行”，
保留原张力指令及冷却基线，不重放已消费指令。

新的暂态与计数保存到既有 director checkpoint。随机候选无需在未提交
边界承诺重现，但成功提交后的诊断与执行状态必须可保存、恢复且不重复。
manifest 补齐新编解码/适配模块快照。归档必须包含 checkpoint，不能仅
保留 manifest、JSONL 与剧本。失败进程摘要另存，避免恢复覆盖失败证据；
保留进程耗时与累计调用统计的不同口径，不将最后进程耗时当全程耗时。

## 10. 实施顺序与修改范围

| 顺序 | 修改范围 | 完成条件 |
|---|---|---|
| A：契约与动作 | contrib 共享 action codec；story_config、story_character 提示；director 当前回合解析；collector/renderer/stub | 自身行动可成功或失败，原始对白保真，旧模式仍可读 |
| B：裁决接线 | story_dramaturgic、story_resolution，调用核心 attempt_to_result | 合法自身行动进入实际结果，其他角色选择及秘密仍受保护 |
| C：重复干预 | contrib 轻量适配步骤、director 状态/冷却/诊断 | 复用核心 helper；区间内重复也可干预，一轮不重复干预 |
| D：归档与评测 | run、provenance、测试、子包 README、配置与对照运行 | 版本可追溯，错误与恢复可核对，真实质量独立验收 |

先验证 A/B 的无反馈运行，再开启 C；不要一次改变行动模式、模型、
预算和导演参数后将质量变化全部归因于某一项修复。
不修改 Concordia 核心代码，不覆盖既有真实结果，不以部署或真实模型
批量请求代替设计审阅。本设计不等于已完成上述实现。

## 11. 确定性与集成验收

## 12. 真实模型验收与取舍

保持相同故事、明确动作模式、固定预算及源码/提示版本，依次对照：

1. speech_and_action + tension_observe：确认行动能兑现，复核不过度拦截。
2. speech_and_action + director：确认重复干预改善推进，未增加越权与泄密。
3. 按原三场景各三次工作流复验，逐项标注 turn_id。具体质量通过阈值在
   批量试验前固定，不能观察结果后改标准。

记录角色辨识、因果与证据来源、秘密边界、重复、实际行动结果、新证据
可用性、导演检查/执行与影响、结局、误拒绝、调用和耗时。完成率、张力
入区间或出现更多旁白不能单独证明改进；角色维持目标但发生新的事实与
选择，才是需要人工检查的推进。允许合理僵局，不保证每次必有圆满结局。

本方案增加少量按需调用和输入/记录字段，换取明确的行动授权与结果来源。
暂不引入长剧记忆、复杂行动规划或全面结构化世界状态；这些只有在真实
对照结果证明必要后，才另行设计。
