## 1. 证据、归因及其限度

证据批次：
[full_story_control/20261019T032409Z](../../../run_results/story_enactment/full_story_control/20261019T032409Z/README.md)。
四组各运行一次；同一冻结源码，只改变模型与动作模式。原始产物只读保留。

| 观察 | 可以得出的结论 | 不能据此断言 |
|---|---|---|
| Sol 动作组第 5、6、10 回合明确暂不插钥匙，第 18 回合暂不示意开柜 | 当前角色决策持续增加或维持前置条件；裁决保留了自身动作限制 | 核心无法裁决一次已明确提出的开柜尝试 |
| Sol 第 13 回合接通电话，但没有产生来电者答复 | NPC 响应授权与信息受众需要明确；现有交互没有闭环 | 来电者应当知道秘密、配合调查或提供真实身份 |
| Sol 的电话、敲门干预合法，但后续继续核对、等待 | 张力变化、事件新颖与因果进展不能互相替代 | 多注入事件就会改善故事，或该次干预完全无效 |
| Gemini 第 5 回合替陈默生成退让，被正确拒绝 | 语义评审保护了一次玩家自主权边界 | 已获准事件不存在漏检 |
| Gemini 第 3 回合把对白中的“启封记录可供查验”写成记录已就绪 | 存在疑似物证来源升级，需要逐项定案并建立明确对照夹具 | 所有记录行为都是伪造证据 |

Sol 的固定样本成绩说明它能处理那些样本，不保证长轨迹的规划、协调、事实
追踪或评审始终正确。四组单次轨迹不构成模型稳定能力排名或严格因果证明。

还有三项报告勘误需要在新 notes 中追加，不覆写旧 README 或 protocol：

1. `speech_only` 不能直接执行物理动作，但不能据此判定所有允许结局不可达；
   自主协商也可能形成结局，必须检查其具体条件。
2. speech-only 可以有合法导演旁白；Sol speech-only 第 15 回合就有电话事件。
3. protocol 中 repetition 开关与实际配置不一致：实际四组均启用，间隔和
   冷却均为 3。组间该参数一致，但预注册记录有偏差，必须披露。

## 2. 推荐方案与责任边界

推荐先实施阶段 A：在现有 contrib/example 链路补足角色动作选择、公开 NPC
回应、物证来源与有效进展提示。保留一人一轮、原始对白、核心原始裁决结果、
一次最终评审、预算与提交边界。阶段 A 不增加每轮模型调用。

阶段 B 是效果验证：先固定上下文，再完整故事。阶段 A 工程通过不等于阶段 B
质量通过，不要求通过强迫角色行动或放宽结局判定来消除所有超时。

私密 NPC 对话另列为阶段 C。现有广播链不支持不同玩家收到同一事件的不同
内容，阶段 A 不能声称修复了 Sol 的完整私密电话交互。需要该能力时，先补充
并审阅受众与提交契约，再实施；不把它隐含塞入提示修补。

本设计明确不做：新增世界状态数据库、通用任务图、另一套停滞检测器、模型
多数投票、拒绝后自动修稿、强制开柜、强制泄密或修改 Concordia 核心引擎。

## 3. Concordia 复用与新增范围

| 已有能力 | 本设计的使用方式 |
|---|---|
| `EventResolution` thought steps | 保留现有顺序，在适配步骤中补上下文与规则 |
| `attempt_to_result` | 继续在独立文档上调用一次；原始返回值不清洗、不替换，是否合法仍需评审 |
| `InteractiveDocument` | 构造规则与 JSON 数据区，不继承上游节拍作为行动授权 |
| `maybe_inject_narrative_push` | 保留真实核心调用、内部建议/随机选择/融合及门控；只校准适配上下文 |
| 角色三问链与现有 ActionSpec | 在既有动作生成调用中要求选择可执行步骤，不新增规划调用 |
| 观察队列与 scene participants | 继续只投递已获准的公开正式事件；不能当作已有私密内容投递能力 |
| `AccountForAgencyOfOthers` | 不接入；它会额外调用其他玩家 `act`，改变当前回合与预算契约 |
| `Plan` | 暂不接入；它增加规划/重规划调用，也不能替代世界响应授权，后续有证据再单独评估 |
| `WorldState` | 不接入；它的模型抽取不构成证据来源或确定性的事实保证 |

关键接线保持：角色输出 → 一次核心动作裁决 → 至多一路导演干预 → 最终旁白
生成 → 程序组装 canonical → 一次独立评审 → 原样提交、投递、归档。

## 4. 阶段 A1：让角色选择本轮可完成的一步

修改 `examples/story_enactment/story_config.py` 中现有 speech-and-action
ActionSpec，不增加 JSON 字段、不新增角色推理组件。输出继续严格为两个
字符串字段 `speech`、`action_intent`，两者不能同时为空。

新增指引应表达以下完整含义：

> 根据你实际收到的观察，回应尚未解决的问题。若决定行动，选择自己本轮可以
> 尝试的一步，描述尝试本身，不预写成功或他人的配合。区分正在执行、等待
> 条件和明确拒绝。等待时说清缺少谁的什么回应或哪个尚未满足的条件；已观察到
> 条件满足时，不要无理由重新提出同一前置条件，可以继续行动、改变方案或
> 明确拒绝。符合自身目标和底线的等待、保留意见与拒绝仍然允许。不必每轮
> 新增核验、登记或签认步骤；必要的程序必须有当前问题作为依据。

补充要求：

- “准备核验”只授权准备；“尝试查看自己可访问的文书”才授权该次查看。
- 自己的疑问得到回应后，选择接受、追问其中具体缺口、改换方案或拒绝；
  不要求所有角色接受同一解释。
- 不把原对白中的将来承诺直接写成已执行动作。GM 不将“准备”改写成完成。
- 角色只读自己的合法观察和私人设定；不得接收导演的未来节拍、目标张力、
  允许结局或其他角色秘密作为行动指令。
- `speech_only` 只校准具体回应与选择，不从对白追认物理动作。

不增加程序规则“连续 N 轮等待就强制行动”；不因动作为空自动拒绝合法对白。
上述属于行为质量指引，不能变成语义评审要求角色积极配合的新硬约束。

双钥匙联合操作本轮不新增授权机制：另一玩家的新动作仍留到其自身回合。
若将来要由一个人的本轮动作完成双方同步转钥匙，必须另行明确已提交的持续
动作、撤回、时序与机械条件。过去一句“我愿意配合”不足以授权其本轮转锁；
也不能把本批尚未尝试插钥匙的轨迹当作联合操作机制已经失效的证据。

## 5. 阶段 A2：区分玩家、公开 NPC 回应与导演新事件

### 5.1 三种权限

| 类型 | 授权与处理 |
|---|---|
| 其他玩家的新同意、交付、签名、转锁、认罪 | 仍不可由当前回合生成；等待其自身选择 |
| 已合法登场 NPC 对当前明确交互的公开直接回应 | 可在配置范围内作为当前动作的直接后果，由同一次核心裁决生成 |
| 创建 NPC、来电、送信、敲门等新外部事件 | 仍只走原导演白名单与干预路径；动作裁决不得偷渡触发 |

“允许 NPC 回应”不代表允许其成为秘密出口。NPC 不自动拥有 GM-only 知识，
不替玩家承诺，不提供配置之外的物证、证词、电话号码、机构认证或法律结论。
若 NPC 没有配置允许的回答，可以产生有依据的拒绝或有限回应；不能用“尚未
确立答复”作为所有公开 NPC 都永远不能回应的通用理由。

### 5.2 最小配置与共享接线

为 `StoryConfig` 增加可选的 `npc_response_rules: tuple[str, ...] = ()`。
每条规则由场景作者明确写出 NPC 名称、登场依据、交互触发、允许回应、知识
限制及公开范围。它是 GM-only 的内容授权，不是已发生事实，也不自动广播。

选择字符串序列以复用现有配置模式，不新增 NPC agent、权限 DSL、运行期事实
抽取器或 NPC 状态数据库。配置加载验证字符串类型、非空内容与序列结构；
自然语言规则是否充分及来源是否满足仍需模型与人工检查，不冒充确定性保证。

空或缺失规则维持旧能力边界，不自动为任意 NPC 赋权。`to_dict/from_dict`、
run config、GM prefab params、manifest 中完整记录此配置；旧配置缺失时读取
为空，不改写旧产物，不在恢复时偷偷换为新的示例默认。与既有配置一致，
非空规则的引入用于新运行，不通过恢复旧状态变更世界授权。

GM prefab 将规则作为显式参数传给动作裁决与最终生成/评审工厂。无需新增
`DramaDirector` 持久化状态；复用现有配置归档与诊断 trace。授权语义使用同一
份共享规则，实例内容作为 JSON 数据传入三个提示，避免生产者与评审漂移。
若未来拆出新生产模块，必须同时加入 provenance 的实际源码清单。

同步消除规则 5/8、共享授权规则和 `run.py` 世界限制中的歧义：导演主动
发起的新外部事件受白名单限制；已登场 NPC 的配置内直接回应受回应规则限制。
不能保留一句“所有 NPC 的新行为都只能逐字来自事件白名单”，再靠另一段
例外提示与其冲突。回应规则仍不能覆盖不可变事实、玩家自主权或信息受众。

首批示例仅加入范围明确的公开邻居回应，例如：

> 邻居必须已因白名单敲门事件合法登场。当前角色实际隔门告知暂不需要帮助
> 时，邻居可公开表示听到了、愿意在被请求时提供普通帮助，或按该告知离开。
> 不披露屋内秘密，不作法律认证，不替屋内玩家同意，不制造证据。仅“准备
> 告知”不算已经说出，也不触发邻居按告知作出反应。

不要求固定台词或必定合作；要测试公开回应确实允许，同时保留拒绝和未知。
NPC 规则只能约束已合法来源；有邻居规则不等于可以在任意回合凭空生成邻居。

### 5.3 当前私密电话的明确限制

现有 `story_dramaturgic` 给 `SendEventToRelevantPlayers` 提供场景参与者
过滤器，没有提供区分每人可见内容的逻辑；该组件在此配置下向每个参与者
发送整段正式事件。`BoundaryEncodingMakeObservation` 只保护条目边界。

因此，阶段 A 只允许在所有场景参与者本来就能感知的公开范围内生成回应。
对于贴耳、未开免提的电话：

- 不能把来电者的具体答复写进全员 canonical，也不能把模型数据标成
  “仅律师听见”就认为其他玩家不会读取它。
- 可以描述有来源且现场可观察的接听、持机等行为；不能擅自决定律师挂断，
  也不能为绕过限制编造对方沉默、拒绝、挂断或身份核验失败。
- 若私密交互无法在现有契约下完成，评测单列为“不支持的私密交互”，不
  将“无答复”计为公开 NPC 修复通过，也不把工程限制编入剧情当事实。
- 角色可以自主选择公开交互，但不得强迫开免提，也不能在不改变条件的
  对照中把原第 13 回合改成免提后宣称已修复原问题。

这是一项已识别的应用层能力缺口。需要完整电话功能时执行 §11 的设计 gate。

## 6. 阶段 A3：固定物证存在、访问和认证的来源边界

继续使用现有共享 `AGENCY_AND_EVIDENCE_RULES`，并在动作裁决、生成、
复核中明确以下区别。不能只在最终旁白提示补一句而让原始裁决结果免检。

| 输入与来源 | 允许确认 | 不允许升级为 |
|---|---|---|
| 对白声称“我手上有启封记录”，既定背景与历史未建立该物件 | 某角色作出该声称 | 记录客观存在、已出示、可供查验或内容真实 |
| 自己明确尝试在现有纸上记录某人的主张 | 写下该主张及其来源 | 主张已获证实、他人已签认或同意 |
| 已建立的文书在自己的合法访问范围，自己尝试查看 | 根据已配置的文书事实给出实际可见内容 | 文书自动真实有效、所有人已看见、其他玩家主动展示 |
| 初始事实或已提交行动建立了某件物证 | 在已建立的可访问范围内处理该物证 | 凭对白推导出另一件未建立的记录或藏匿物 |
| 私密设定写明真相 | 用于约束不可能结果 | 物证已被找到、角色已知道或公开认证真相 |

访问合法不能替代物件存在的依据；对白可真可假，也不是“什么都不能发生”。
角色自己的新记录、普通动作造成的可见变化仍可合法发生。评审必须同时检查
原始核心结果与 canonical，不能通过删掉非法核心结果的一句而让整轮通过。

把 Gemini 第 3 回合保留为需人工定案的原样案例；另建来源完全明确的正反
夹具验证规则，不能依赖有歧义原例支撑所有正确性断言。此修补提高提示边界
与可检验性，不宣称建立了确定性证据验证器。

## 7. 阶段 A4：导演判断有效进展，而不只制造新事件

### 7.1 在现有重复判断上下文中校准

落实旧 run4 设计 §6 的内容，修改 `repetition_push.py` 的适配规则，原核心
helper 不变。当前动作模式已出现停滞证据，足以提出本设计；原先未实施的
阶段 C 不追溯标记为已经完成，也不凭本设计自动执行生产修改或付费测试。

判断时区分：

- 首次发现明确阻塞、新的有来源信息、真实动作结果、解决先前问题的回应、
  自主接受/拒绝或改变策略，都可能是进展。
- 多次重述同一阻塞、重复准备、不断要求同样登记、只更换措辞，不自动算
  新进展。首次有意义的程序要求和无依据重复加码应分别判断。
- 移动、照明或登记有时是必要进展，不能全部贬为无效微动作；要看是否使
  现有问题更接近明确结果。
- 有新冲突不等于停滞；没有物理变化不等于停滞；行动受阻也不等于无进展。
- 当前未提交候选、未来节拍和私密真相不是已经发生的公开进展。

不增加一次“是否停滞”调用，不把模型 No 程序改为 Yes，不按轮数强制干预。

### 7.2 改善已有干预建议

在 `drama_director._generate_directive`、`director_note` 及 repetition 的
建议约束中表达：基于已有历史中的具体阻塞，优先提出与当前可行动问题有关
的合法变化；不要仅为新颖而继续堆叠打断和核验任务。不得指挥玩家改变目标、
认罪、配合或选择某个结局。

限制如下：

- 白名单、张力范围、评分标准、节拍时限、冷却、间隔、张力优先与一轮至多
  一路导演干预均不变。
- 不增加候选重抽、程序排序或新规划调用；核心随机选择保留，适配上下文
  约束所有建议，而非事后挑一个“最推进”的结果。
- 原 pending 指令可以无合法建议；不为凑执行数放宽授权。已有零建议路径
  原样保留。
- NPC 对当前交互的有限直接回应属于动作后果，不计作又一次导演干预；
  创建新外部事件仍必须走导演门控，不能用 NPC 标签绕开一轮一路限制。
- 不要求最终评审因“推进不够”拒绝本来合法的事件；合法性与行为质量分开
  评价，避免引入新的语义误拒绝。

不要求导演保证收敛。没有合法外部手段能够解除由玩家自主拒绝形成的僵局时，
允许正常超时；没有证据支持时不能自动认定为法院结局或任何其他结局。

## 8. 不变的工程契约

阶段 A 继续保留：

1. 角色动作双字段、最终输出单字段 `stage_directions`、评审严格
   `{"valid": bool, "reason": str}`；不增加生产模型结构化字段。
2. 非空动作恰一次核心裁决；无意图跳过。NPC 公开回应在这一次裁决内生成，
   不另调用 NPC 模型。核心返回值原样记录并进入生成与复核。
3. original speech 逐字保留；canonical 在评审前确定性组装；获准后不重写。
4. 裁决、生成与复核使用一致的来源规则及 NPC 配置；最终生成和复核继续
   读取同一次冻结的公开历史。不将私有 trace 放入公共历史。
5. 拒绝即停止，无自动修复、二审或换模型续写；未获准结果不投递、不提交、
   不消费干预。失败消耗累计。
6. path A：裁决/生成/复核前耗尽，本步未提交；path B：获准后评分/节拍
   判断耗尽，本步按原路径恰提交一次，恢复不丢。
7. 不修改节拍含义、结局条件、预算或回合上限来掩盖超时；不默默改变默认
   动作模式。新世界配置用于新目录；旧运行不被变成新方案的实验组。
8. 保留 dirty worktree、既有过程工作区和运行产物；本设计不要求 commit、
   worktree、合并或清理。实施记录提供实际文件范围与前后快照。

## 10. 验证与验收

### 10.1 确定性工程测试

使用 `MockModel` 或既有确定性 stub，覆盖实际生产接线，不以 stub 的语义判断
证明真实模型质量。至少包括以下边界：

1. 角色收到的实际 ActionSpec 含执行/等待/拒绝指引，未收到隐藏事实或结局。
2. NPC 配置往返、缺省为空、参数传递及归档一致；错误结构在建模前明确失败。
3. 已登场邻居的公开有限回应经过真实核心调用、原样 evidence、生成、复核、
   下一玩家观察、JSONL、checkpoint 和 FDX；未丢弃或降格核心结果。
4. 邻居未登场、仅准备告知、替另一玩家配合、私密内容被全员广播等非法候选，
   注入 reviewer 拒绝后不提交、不投递、不消费；已有各阶段失败测试可复用。
5. “持有记录”的未核实声称与新记录行为、合法查看已有文件构成正反对照；
   原始裁决非法但最终旁白删掉该句时，整轮仍拒绝。
6. 一次原核心调用、原返回值变化能改变结果或触发拒绝的变异检查继续成立；
   NPC 功能无新增独立调用，纯对白仍零次动作裁决。
7. 重复 helper、导演优先级、冷却及最多一路干预不变；公开 NPC 直接回应
   不作为独立导演干预，也不能暗中创建一个未获准的新事件。
8. 多段对白、非空旁白、来源规则、拒绝、预算 path A/B、API 错误与恢复
   消耗契约按实际受影响范围回归。

代码检查按仓库要求执行 pytest concordia、pytest examples、pylint
--errors-only、pyrefly，以及改动文件的 pyink/isort 与 diff 空白检查。既有
依赖/类型错误与新增问题分列，不以一次历史 GREEN 替代当前验证。

### 10.2 固定真实样本：先定位哪个环节改善

执行前另行冻结协议、调用上限、模型、采样参数、版本、来源哈希和人工标签。
本文件不授权调用。不顺带给每轮加重试，生产已有 API 重试按实际层级披露。

最少覆盖以下样本族，每族须包含能区分规则的正反样本：

| 样本族 | 关注点 |
|---|---|
| 条件已满足/尚未满足/明确拒绝 | 角色能继续、等待有依据、拒绝被允许；不按必须开柜判分 |
| 实际告知邻居/仅准备告知/邻居未登场 | 公开回应、意图粒度与登场来源 |
| NPC 有限自述/权威身份认证/秘密泄露 | 生成 NPC 言语不等于认证内容或授予知识 |
| 对白声称有记录/自行记笔记/查看已建立文书 | 物证存在、访问与真实性分离 |
| 重复程序/新阻塞结果/有效回应或自主拒绝 | 重复检测既有敏感度又有特异度 |
| 已接听但未开免提 | 明确标记私密功能未覆盖，不错误算作公开回应通过 |

对固定来源分别检验三个层次：角色输出；真实核心裁决→最终生成→复核；
注入有效/无效候选的独立评审。演员生成存在随机性，不和独立评审正确率混算。
比较版本时使用同一冻结上下文与采样参数；动作、NPC、物证、导演提示分项
做消融，不能一次修改全部后把改善归给某一个提示。

固定关键边界以人工标签零违规为门槛；合法对照也必须通过，不能只靠全拒绝。
不支持的私密样本单列，不计入通过分母。人工标签保留证据文本和理由，歧义
样本先裁定；任一关键边界未过则修复并建立新批次，不挑选补跑覆盖原失败。

### 10.3 完整故事对照与质量判定

固定样本通过后，另行授权新目录完整故事对照。推荐主对照固定
`speech_and_action`、Gemini/Sol、当前时限与预算，分别比较冻结基线与候选
版本。若只复用本批为历史基线，必须披露调用时间和随机轨迹差异，不能称为
严格配对因果实验。speech-only 可作为附加研究，不作为物理动作完成的门槛。

预注册运行次数和失败处理；每组不因结果不满意而重跑。逐轮人工标注：

- 有来源的新信息、实际行动结果、问题回应、自主选择及其来源。
- 新增等待条件、条件实际满足、重复重提及是否有必要依据。
- NPC 请求是否获得授权范围内回应，是否涉及不支持的私密通道。
- 导演干预的事实、后续是否被响应、是否增加无关事务。
- 越权、物证升级、秘密泄露、误拒绝、漏检与结局具体条件。
- 所有停止原因、调用/重试/预算/耗时；进入 b4 不等于结局已成立。

区分三种结论：工程链路通过、固定语义样本通过、完整故事质量通过。
质量改善至少需要具体轨迹显示：原阻塞得到合法响应，角色按自己的选择继续
或明确拒绝，旧程序循环没有仅换成新的循环，且没有用越权换进展。若要宣称
“已演示故事可完成”，至少须有一条允许结局全部条件真实成立的合法轨迹。
不能用没有 error、旁白变多、干预变多或轮数更短替代这些证据。

合理僵局的 beat_timeout 可以是正确终止，但不能标成故事完成。所有轨迹
仍停滞时质量目标未达到；回到具体缺口分析，不能直接再升级模型或放宽守卫。

## 11. 阶段 C gate：私密 NPC 回应需要独立受众设计

要修复 Sol 第 13 回合这类真实私密通话，单改 AGENCY 提示不足。若完整故事
需要该能力，补充设计须在实施前明确并通过审阅：

1. **公开与私密内容分离。** 当前全员 canonical 只包含公开可感知事实；
   NPC 私密回应有明确接收者和来源，不能放在公共字符串中靠标签隔离。
2. **一次批准与原子提交。** 评审检查公开事件、私密负载及接收者；未通过
   不投递任何一部分。恢复时不丢失、不重复投递，失败消耗继续累计。
3. **知识隔离。** 私密负载只进入授权接收者的观察和相应 GM 私有上下文，
   不进入其他玩家记忆、公开 DisplayEvents、公共张力评分或节拍已公开事实。
   全部接收者合法得知或玩家自主公开之前，不认定为公共揭示。
4. **调用和 schema 成本。** 明确保留一次最终评审的实现是否可行；如扩展
   最终输出单字段契约、collector/checkpoint/导出或增加调用，须显式列出
   版本、预算和迁移决定，不伪称与阶段 A 的不变契约相同。
5. **复用现有队列。** 优先基于现有按玩家队列与 contrib 适配实现定向投递，
   不先重写引擎；存在按玩家队列不等于已有安全的内容拆分和提交实现。
6. **验收场景。** 律师听见 NPC 自述但未核验；其他人只见接听动作；律师
   后续可自行选择披露或不披露；挂断、拒绝、预算耗尽、恢复均不串知识。

阶段 A/B 可以先交付并独立评价。阶段 C 未实施之前，报告必须持续列出私密
通话限制，不能以公开邻居回应通过宣布全部世界交互闭环。联合行动授权同理，
有实际需求与证据后另立设计，不与私密观察扩展一并默认启动。

## 12. 建议的实际执行次序

先写阶段 A 的实施计划并审阅：基线与来源夹具 → 来源/授权共享规则与公开
NPC 接线 → 角色动作指引 → 导演上下文 → 确定性整体验收。以上变更独立列项，
方便后续消融，不把完整故事的随机结果当作工程回归。

随后冻结并执行阶段 B 的固定样本；通过后进入新一轮完整故事对照。若需求
明确包括贴耳电话的实质答复，则先完成阶段 C 补充设计与工程验收，再把这种
场景纳入完整功能的通过条件。本轮只交付本文，不修改生产代码或旧运行产物。
