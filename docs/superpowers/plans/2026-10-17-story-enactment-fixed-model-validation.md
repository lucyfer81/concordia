## 3. 准备、检查并冻结样本

### 3.1 共同上下文

从当前 example 配置工厂构造并保存故事/GM 配置，不启动 simulation.play。
固定初始公开事实、GM-only 约束、玩家名单与底线、环境白名单。各夹具再
明确提供其已提交历史、公开历史字符串、当前角色、原始对白、意图、结果
和干预证据；本轮不由模型补齐任何这些输入。

公开历史 getter 必须返回冻结文本；director 窗口是对应历史的近期窗口。
需要窗口外事实的夹具，要保证它确实只位于较长公开历史内，窗口长度按
`max(scoring_window, 20)` 处理。R 和 A 都使用各自冻结的同一套上下文格式。

`case_id`、`expected_valid`、人工判定标签和“合法/非法”文件名不进入模型
提示。它们只作为评测元数据，防止标签泄漏。

### 3.2 R 组：16 个固定复核夹具

F1–F7 保留上一轮固定输入：从旧 probe 的 `FIXTURES`、对白常量与冻结
报告核对后移植**数据**，使用新版生产步骤形成提示。不要为了更容易通过
而调整这些样本。

| 编号 | 固定场景 | 预期 valid |
|---|---|---|
| F1 | 保留停电和烛光，省略“仍未达成一致”的背景重述 | true |
| F2 | 同一环境事件忠实改述为“暴雨更急……” | true |
| F3 | 只留雨声，遗漏停电 | false |
| F4 | 把停电写成恢复供电 | false |
| F5 | 无来源地新增众人同意将老宅过户给林雪 | false |
| F6 | 干预候选只有已有僵局重述，没有新事件 | false |
| F7 | 裁决撬锁受阻，旁白却写开门取出物证 | false |
| F8 | 林雪请求律师展示，raw result 与旁白却替律师执行展示 | false |
| F9 | 当前玩家是律师，明确尝试展示手边已有可访问文件，结果有设定来源 | true |
| F10 | 律师早先已在自身回合展示；本轮只重述已公开且未变化的状态 | true |
| F11 | 自身尝试与物证无关，raw result 与旁白凭空产生纸灰物证 | false |
| F12 | 与 F11 使用完全相同的 raw result，旁白删去纸灰，仅保留合法自身动作 | false |
| F13 | 对白声称“各方已同意”，无行动、空旁白，且不违反其他底线 | true |
| F14 | 自身明确记录“我提出暂停，待各方确认”，旁白只确认该带归属的记录行为 | true |
| F15 | 没有各方自己的选择来源，旁白直接认证集体同意 | false |
| F16 | 笔记含未核实的集体同意，旁白还保证其内容都是已证实客观事实 | false |

新增样本的完整字面文本、事实来源和预期标签必须在付费运行前写入
`fixtures.json` 并人工检查，至少确认：

- F8/F9 的关键区别是**当前行动者与其自身授权**，不是文风差异。F9 的
  文件已经存在、可访问，内容有设定来源，披露不违反角色底线。
- F10 的展示确实已在历史中发生；不把当前请求当作过去授权。
- F11/F12 的 raw result 逐字一致；F12 的最终旁白确实没有纸灰，但仍须
  拒绝整轮裁决。禁止只按最终旁白是否合法给它标 true。
- F13 不能同时带入认证同意的旁白；F14 没有笼统的真实性担保。
- F15/F16 缺少真实同意来源，不能误造为“历史已经同意但仍拒绝”的样本。
- 每个样本的角色、意图、裁决结果、旁白和历史一致，除目标违规之外不混入
  其他明显问题。预期合法样本不能靠脚本 valid=true 证明其合法性。

Luna 原始第 8 回合保留为待人工定案的歧义材料，本批不追加真实调用，
不纳入 16 个计分样本。若将来纳入，须在下一批运行前固定标签。

### 3.3 A 组：四个固定行动裁决输入

| 编号 | 当前玩家与自身尝试 | 人工检查重点 |
|---|---|---|
| A1 | 林雪向周律师请求展示文件 | 可以完成请求；不替律师主动展示，不凭请求公开文件内容 |
| A2 | 周律师自己展示手边已启封、可访问的既有文件 | 信息有设定来源，披露合法；不附赠其他证据或他人选择 |
| A3 | 王婶走近陈母劝其拿钥匙，不接触花瓶或物证 | 不替陈母交钥匙，不凭空碎花瓶、产生纸灰或推进未来剧情 |
| A4 | 当前玩家在自己的便笺记下“我建议暂停，尚待各方确认” | 可以完成记录，不认证集体协议，不凭空生成签字 |

固定完整对白与 action_intent，明确物品位置、可访问性和历史条件。
“写下便笺”是当前自身动作；不得把它变成已获各方认证的物证。成功、
失败、受阻都按设定是否有依据判断，不按成功率评分；仅重述未来意图、
没有给出实际结果，也应在人工标注中指出。

### 3.4 冻结协议文件

在第一笔真实请求之前写出并固定：

- `protocol.json`：协议版本、两模型实际名称、R/A 的次数与执行顺序、
  通过标准、无重试策略、最大真实调用数 120、异常/中断策略。
- `fixtures.json`：全部 R/A 完整输入；R 的预期 valid、各例的人工理由和
  事实来源；A 的判断维度。标签不进入模型输入。
- `source_snapshot.json`：探针、夹具、生产裁决/复核/prefab/模型适配器
  及相关文档工具的源码内容或可验证快照、文件哈希；不要只记录 Git HEAD。
- 两模型各自实际生效的采样参数和请求设置。保持与生产调用一致，不临时
  强制 temperature=0、增加输出额度或更换 reasoning 参数来提高通过率。

明确预定调用顺序，例如每个重复轮次依次遍历 case，再依次调用两模型。
采用确定顺序即可，不声称因此消除了顺序或服务端时间差异。

## 4. 实现 R 组的生产路径探针

每条 R 记录均使用当前 `story_resolution.make_final_output_step`：

1. 建立只包含该夹具的确定性 director/公开历史上下文。
2. 调用生产最终步骤；使用测试专用 `LanguageModel` wrapper，对第一次
   最终生成请求返回 `json.dumps({'stage_directions': 固定旁白})`。
3. 由生产代码解析旁白、组装 canonical event、构造独立复核文档。
4. wrapper 对第二次请求转发给真实模型，捕获实际 prompt、请求参数及原始
   返回文本。每个 case 使用全新的 wrapper/文档，不带上一次的对话状态。
5. 由生产步骤继续执行其原有判定；记录最终批准或异常，与解析分类交叉核对。

wrapper 必须断言第一次是当前生产生成任务、第二次是复核任务；任何第三次
文本调用、choice 调用或意外路由立即记为探针错误，不能转发给 API。
不得自行生成第二份手写 review prompt，也不得用脚本模拟真实复核结果。

一次 R 包含一次固定生成响应和一次真实复核。固定生成响应**不是付费请求**，
单独记录 `synthetic_generation_calls`。完整 R 组应为 96 次模拟生成、96 次
真实复核；不把生产模型接口的合计调用数误算成 192 次真实调用。

复核参数由生产步骤传出（当前 `max_tokens=1000`、`terminators=()`），
wrapper 只透传并存档，不另写一套采样配置。

## 5. 实现 A 组的生产路径探针

每条 A 记录使用当前 `make_action_adjudication_step` 和真实
`event_resolution.attempt_to_result`：

1. 用真实 director 生命周期或等价的确定性 fixture 上下文装入当前角色的
   JSON 行动契约，保证原始对白和自身意图已正确解码。
2. 显式传入冻结的 `public_facts` 与 `public_history` getter；填好对应
   director 事件窗口和 GM-only 限制。
3. 仅调用行动 thought step 一次，真实模型回答核心问句一次。
4. 保存 SDK/provider 返回的原始文本、核心实际拼装的完整 action_result、
   director evidence 与私有诊断。断言返回值和记录值一致。

不调用角色模型、导演融合、最终生成、语义复核、节拍完成或张力评分。
每条 A 恰为一次真实调用，完整 A 组共 24 次。
使用 spy 观察真实核心调用，不能 monkeypatch 核心返回来代替真实模型结果。
生产步骤已负责独立文档和原始返回保真，探针不得抽句、删句或改写其结果。

## 6. 付费运行前先完成无网络演练

测试使用 `MockModel` 或确定性 provider spy，不需要 API key，至少验证：

1. 两组任务均走上述生产工厂；R 的模拟生成与真实转发槽位恰为 1+1，
   A 的核心调用槽位恰为 1；多余调用被拒绝。
2. R 的 16 例 × 2 模型 × 3 次形成 96 个唯一键，A 为 24 个唯一键；不存在
   重复、漏项或通过率分母动态缩小。
3. 同一 case 的两模型、各次重复 prompt 字节一致；模型名不拼入提示。
   R 的实际 canonical 与夹具固定旁白/原对白完全一致。
4. 当前生产的公开历史数据段、更新后的复核问题后缀确实进入实际 prompt，
   且生成与复核所见公开历史一致；不只是检测探针内的预期字符串。
5. valid=false、malformed JSON、重复键、错误字段类型、API 异常和无可见
   文本响应分别分类；不把任意 `StoryOutputError` 当成正确拒绝。
6. 协议在请求前落盘；输出目录已存在时拒绝覆盖；请求前记录 attempt_started，
   响应后立即存档；意外中断不会默默重发一个已经开始的请求。
7. 两阶段真实转发槽位总上限为 120；SDK 的自动重试与探针外层重试都关闭。
   若复用预算 wrapper，应放在实际转发路径，不能让固定生成响应消耗真实
   API 尝试上限，也不能在每例失败后重置累计计数。

另做一次 dry-run：输出将实际发送的全部提示和哈希，真实客户端构造次数
必须为零。检查夹具、标签、路由、上下文和数量后再冻结最终协议。
新增工具按仓库要求跑适用的测试、pylint、pyrefly、pyink/isort；真实运行
前确认没有修改生产逻辑。CLI 的实际命令与检查退出码写入本批 README。

名称只是约定；固定一个命名体系并在 report 里引用实际文件。每条结果至少含：

- stage、case_id、model 实际名称、repetition、唯一 attempt_id。
- 输入/提示哈希、请求参数、开始与结束时间、耗时、状态与异常分类。
- 原始响应路径；R 的 canonical、解析 verdict/outcome；A 的 raw provider
  文本与核心完整 action_result。API 未返回文本时只留异常记录，不伪造响应。
- 模拟生成计数、真实 API 调用计数、可获取的 token usage；取不到时标明
  不可用。记录供给模型的提示及实际请求设置，凭据不得进入产物。

记录每笔请求前后的状态。语义失败继续完成预定未运行条目，不自动修稿或
重试；网络/接口错误计为本条 api_error，不能补一条成功响应覆盖它。若
认证、连接或探针故障使剩余调用无法有效执行，停止并记录未运行键。

中断后，已经 started 但没有落盘响应的条目标为 indeterminate；不自动重发，
不宣称请求未送达或未收费。允许继续尚未开始的预定条目，但批次因此不能
通过完整性门槛。需要重测时使用新批次和新协议，不删除这批证据。

单次明确拒绝不触发提前通过或删除剩余用例。零错误标准只在预定条目完整
且全部已分类后计算；API 调用计数不能仅用成功响应文件数量反推。

## 8. 分类、人工审查与通过标准

### 8.1 R 的机器分类

按生产 `_validate_review` 的严格格式语义解析：可兼容同样的外层代码围栏，
仅两个字段 valid/reason，类型正确、无重复键。先完成格式分类，再比较标签。
生产校验器对“合法格式但 valid=false”会抛异常，不能据异常类型直接认定
格式错误或正确拒绝。

| 预期/响应 | 分类 |
|---|---|
| 合法夹具 + valid=true | correct |
| 合法夹具 + valid=false | false_rejection |
| 非法夹具 + valid=false | correct |
| 非法夹具 + valid=true | missed_detection |
| 非法 JSON、额外/重复字段、类型错误 | malformed |
| provider/网络错误或 provider 抛无可见文本异常 | api_error/provider_error |
| 未启动、状态不确定或探针错误 | incomplete/indeterminate/harness_error |

调用生产解析器或其现有解析 primitives，并验证解析行为一致；不增加宽松
JSON 修复、关键词判定或把空响应当 valid=false 的回退。

R 完整时每模型 48 条：18 条预期合法、30 条预期非法。每模型必须零误拒绝、
零漏检、零格式错误、零 API/provider 错误，且没有缺失/不确定/探针错误。
两模型均满足才算 R 通过。

人工阅读所有理由，尤其 F2、F8–F16；另记“标签正确但理由错误/不相关”，
不能将其描述为语义理解已验证。若怀疑夹具或人工标签错误，保留原计分结果，
记录争议；重新定案后在新批次生效，不改本批标签来获得 PASS。

### 8.2 A 的人工标注

每份原始返回均需人工标注，不能让生成它的模型自评作为最终标签。
每条至少记录：

```json
{
  "attempt_id": "A01__m1__r1",
  "status": "labeled",
  "outcome": "success_or_failure_or_blocked",
  "unauthorized_player_action": false,
  "fabricated_evidence": false,
  "illegal_disclosure": false,
  "ungrounded_plot_event": false,
  "definite_grounded_result": true,
  "pass": true,
  "reason": "填写实际结果、来源及人工判断依据"
}
```

这是字段示意，执行者必须回填真实标签，不能批量复制默认 false/true。
拒绝判断他人选择、未公开秘密或没有成功开柜，本身不是失败；必须结合
具体世界条件判断。也不能把无依据的成功或受阻当成合法结果。

每模型 12 条均有完整人工标签，明确越权、伪造物证、非法泄密、无来源
推进事件为零；所有结果有明确且受设定支持的后果，API/provider/探针错误
为零。争议未定案时不宣布 A 通过。模型间允许产生不同合法后果，不要求
文字或成功率相同。

### 8.3 本轮结论

`overall_pass` 只有在 R 与 A 的数量、哈希、机器分类和人工审查均完成，
且两模型各自达到门槛时才能为 true。程序不应先写 PASS 再补人工标签。

单例一次失败使本批相应门槛不通过；不要把三次重复当多数投票。有限样本
全过也仅是进入下一验证阶段的门槛，不构成模型永不出错的保证。
