## 1. 本轮任务与范围

基于已经通过阶段 A 工程验收的当前源码，准备并执行一次固定样本实验。
检验角色具体选择、公开 NPC 回应、物证来源、评审边界及重复判断。
完成归档、标注和汇总后，停在结果审阅点。

本轮只检验候选版本是否达到固定样本门槛；不做旧版本对照或消融，不宣称
相对旧版本的改善幅度或因果归因，也不宣称完整故事质量已通过。

约束：

- 不修改生产代码、生产提示、核心 helper、既有评测工具或旧运行产物。
- 不执行完整故事，不扩展私密 NPC 通道或联合行动，不启动新功能开发。
- 不 commit、stash、clean、checkout、创建 worktree 或回滚既有工作。
- 只使用 `AI_MODEL_4`（`gpt-6.1-sol`）与 `AI_MODEL_1`
  （`gemini-3.8-flash-high`）；凭据仅从既有环境配置读取，不打印或归档。
- 每个样本每模型一次，顺序执行。关闭 SDK/API 包装重试，禁止择优重跑、
  修稿、补偿请求或用另一模型补位。
- 所有终端命令使用 Bash，先 `source venv/bin/activate`。

## 2. 批次目录、脚本与调用预算

新建此前不存在的目录：

```text
run_results/story_enactment/world_response_fixed_probe/<UTC时间戳>/
```

先为本批编写独立的 `probe.py` 与确定性 `probe_test.py`，可以放在批次
目录内。复用现有探针的模型构造、请求归档与包装器，以及实际生产工厂。
不要为此新建通用评测框架。脚本与测试在冻结前完成；随后一并归档哈希。
新 Python 文件遵循项目许可头与编码规范。

`adjudication_chain_probe.py` 的旧夹具和 120 次协议是硬编码历史实验，
不能直接原样执行来替代本批，也不得改动其旧协议。其他旧探针仅供复用
适用工具；其调用限制和 `sample_choice` 支持范围必须重新核实。

| 分组 | 固定样本 | 每例每模型调用上限 | 两模型组上限 |
|---|---:|---:|---:|
| ACT：真实角色决策链 | 3 | 4 | 24 |
| CHAIN：核心裁决→最终生成→评审 | 6 | 3 | 36 |
| REV：固定候选独立评审 | 8 | 1 | 16 |
| REP：真实重复判断→可选建议/融合 | 3 | 3 | 18 |
| 总计 | 20 | 每模型最多 47 | **94** |

这是上限，不是必须消耗的额度。上游失败或 REP 判断不重复时，后续调用
正常跳过；不得把节省额度移给其他样本、重试或新增研究。

### 实际请求边界必须硬限额

计数落实到 SDK 向提供方发起请求之前，不能只数 thought step 或
`LanguageModel.sample_choice`。每次真实请求尝试，包括 API 错误和超时，
均占一个额度；同时执行全局、每模型、每组和每例的上限。

特别注意：当前
`concordia/contrib/language_models/openai/base_gpt_model.py` 的
`sample_choice` 会在答案不匹配时循环请求。仅设置 SDK `max_retries=0`
不能关闭这类重试。实验专用包装器须为每个逻辑调用分配唯一 slot，实际
请求代理在同一 slot 的第二次请求发出前阻止它；保存第一次原始答复及
解析失败，不发第二次请求。不修改生产适配器或复制核心 helper。

ACT 的每个推理/动作调用各有一个 slot；CHAIN 的裁决、生成、评审各一个；
REV 一个；REP 的选择判断、建议、融合各一个。用无网络测试证明隐式第二次
请求会在到达模拟提供方之前被阻止，且不会消耗其他 slot 的额度。

## 3. 准备并冻结 20 个完整夹具

每个夹具需保存完整字面输入，不只保存下表摘要。公共背景、已提交历史、
当前角色、合法访问、物件存在、GM-only 事实、玩家名单/底线、NPC 规则、
白名单与当前证据必须明确。不要让模型生成夹具或预期标签。

两模型使用相同的冻结输入、规则与上下文构造。固定 InteractiveDocument
选项排列所用 RNG，使相同选择题的选项顺序可对齐；不声称提供方执行了它
没有接受的 seed。记录可对齐提示的字节哈希。上游真实输出不同时，后续
提示自然不同，应如实归档，不能为了字节一致而替换上游结果。

标签、case_id、预期答案、评分说明和“合法/非法”文件名不得进入模型提示。
角色仅接收自己的设定与合法观察，不接收其他角色秘密、未来节拍、允许结局
或 GM 的 NPC 授权规则。

### ACT：角色会不会作出具体选择

| 编号 | 冻结情境 | 判定重点 |
|---|---|---|
| ACT01 | 角色此前等待的具体条件已由公开历史满足 | 可继续自己的动作或作出有依据的取舍；不无理由重提同一前置条件 |
| ACT02 | 条件确实尚未满足，相关决定属于另一玩家 | 指出具体缺口、作出合法自身选择，不虚构他人配合 |
| ACT03 | 当前目标或硬约束支持拒绝该请求 | 允许明确拒绝，不把“必须合作、必须开柜”当通过条件 |

使用真实 `story_character` prefab 的三问链与当前双字段 ActionSpec，
通过真实 `act()` 获得角色输出。关闭情绪与关系刷新等非本批研究组件，
不运行完整 simulation，不添加导演/评分调用。dry-run 确认每例为三次
角色推理加一次动作输出，最多四次真实请求；不符合时先修正实验配置。
保存整个决策链提示与输出，严格使用现有 action codec 解析动作。

预期行为应列出允许的选择及不允许的事实升级，不能把某一句参考台词或
某个必选动作当作唯一答案。三例能说明固定情境下的表现，不能据此估计
角色在长故事中的稳定推进率。

### CHAIN：世界是否正确回应

| 编号 | 冻结情境 | 通过条件 |
|---|---|---|
| CHAIN01 | 合法敲门已提交；当前角色实际隔门告知不需帮助 | 能产生规则范围内公开的有限回应，不替玩家决定 |
| CHAIN02 | 邻居尚未登场，但角色试图向其交互 | 不生成邻居已经听见并回应；只裁决有来源的自身尝试及其有限结果 |
| CHAIN03 | 邻居已登场，角色只是准备告知 | 不把准备变成已告知，不触发邻居按告知回应 |
| CHAIN04 | 对白声称持有启封记录，无物件存在依据；自身动作与制作/展示记录无关 | 声称保持归属，不生成记录存在、可供查验或已认证 |
| CHAIN05 | 现有纸张已建立，角色尝试记录某人的未核实主张 | 可以写下主张与出处，不认证内容、他人签名或集体同意 |
| CHAIN06 | 文书存在、访问权及内容均有来源，角色实际尝试查看 | 保留合法查看结果，不扩大真实性、其他玩家行动或知情范围 |

每例调用真实 `make_action_adjudication_step`，由它原样调用一次核心
`attempt_to_result`；将真实原始返回值不清洗、不改写地交给同模型的
`make_final_output_step`，执行生成、canonical 组装与独立评审。

显式传入当前 `npc_response_rules`，冻结 public_history getter；不能
在夹具中用“仅当敲门后才能回应”的规则文字代替已提交敲门历史。

CHAIN02–04 是限制情境，不是预设必拒绝的非法结果。模型应生成合法的
准备、有限或受阻结果，整轮可以获准。核心若越权但评审拦截，应分列
“裁决失败、守卫成功”，CHAIN 整例仍不通过；不能用拒绝率替代可用性。

### REV：评审既接受合法结果，也拒绝违规结果

| 编号 | 固定注入 | 预期 valid |
|---|---|---|
| REV01 | 已合法登场的邻居给出配置范围内公开回应 | true |
| REV02 | 自己在现有纸上记录带出处的未核实主张，无事实认证 | true |
| REV03 | 没有登场历史却生成邻居回应 | false |
| REV04 | 对白中的物证声称升级为客观存在或真实性认证 | false |
| REV05 | raw action_result 越权，最终旁白删掉违规句 | false |
| REV06 | 合法来电已建立，贴耳未开免提的私密答复进入全员 canonical | false |
| REV07 | 无事实来源，却为绕过私密限制声称对方挂断，且身份核验失败 | false |
| REV08 | 已登场 NPC 公开披露它无权知晓的 GM-only 秘密 | false |

REV05 的非法 raw result 与干净旁白必须同时进入评审；不能只审旁白。
REV06/07 建立真实电话前置情境，保持当前玩家自己的行为合法，尽量隔离
受众或无来源后果这一目标违规，不混入凭空来电等无关违规。

可用实验 wrapper 在真实最终工厂的生成调用返回冻结的单字段旁白，捕获
程序组装的 canonical 与完整评审提示，仅评审调用转发真实模型。生成
stub 不计真实调用，真实评审仍由生产路径解析并决定批准或拒绝。不得
手写一套简化评审提示、替换生产规则或用自定义宽松 JSON 解析代替它。

私密功能本身仍“不支持”；REV06/07 只检验是否拦截错误输出，不能据其
通过宣称私密对话功能可用。

### REP：重复判断与建议质量

| 编号 | 冻结的已提交历史 | 预期判断 |
|---|---|---|
| REP01 | 连续重复同一准备/核验请求，无新事实、结果或有效回应 | 重复：Yes |
| REP02 | 最近首次实际得到一个明确受阻结果，改变了可行行动信息 | 不重复：No |
| REP03 | 最近出现首次实质回答或新的自主拒绝，改变了互动状态 | 不重复：No |

调用真实 contrib repetition step 与核心 helper；fixture 通过正常组件
生命周期形成满足检查门控的状态，不额外执行真实评分、节拍或指令生成。
需要的暖场提交使用 stub，不计真实调用，内容提前冻结并标明来源。

REP01 预先确认白名单存在至少一个与公开问题相关的合法变化机会，不要求
唯一台词或指定玩家配合。判断 Yes 后最多再调用建议、融合各一次；原返回
值保留。人工另评：建议是否有来源、守住自主权与秘密边界、与当前具体
问题有关，以及是否只增添无关核验事务。合法但无关的变化不能算推进质量
通过；没有实际新变化不标为成功干预。此组不另调用最终生成或评审模型。

当前候选保持未提交标记；REP02/03 所依赖的新进展应已在历史中提交，
不能拿未提交候选、未来计划或隐藏真相冒充已发生的进展。

## 4. 无网络预检与正式冻结

在任何真实客户端创建或请求前完成：

1. 完成脚本与确定性测试，验证 ACT 的 4 次、CHAIN 的 3 次、REV 的 1 次、
   REP 的 1–3 次请求路径，以及上游失败跳过下游的行为。
2. 用假的提供方验证 SDK 重试关闭、选择题隐式重试被阻止、预算超限在
   发出请求前阻止、started 标记落盘后才允许发出请求。
3. 捕获实际提示，检查 NPC 数据与已提交历史、物证存在/访问依据、当前
   受众、原始裁决和 canonical 均到达正确位置；原始对白保持逐字一致。
4. 冻结完整 fixtures 与预期标签。歧义输入先澄清，不付费后再改标签来
   适配结果。记录标签制定者及检查者的实际身份。
5. 写入并计算 `protocol.json`、`fixtures.json`、`source_snapshot.json`
   的哈希；保存 dry-run 结果和实际可执行命令到 README。

协议必须包含：模型映射、两模型和各组预算、每例 slot 列表、执行顺序、
真实请求参数、超时、零重试设置、标识差异披露、通过标准、故障停止规则。
模型名可从配置读取并验证，禁止把 `.env` 全文或凭据放进快照。

源码快照至少覆盖生产 provenance 清单，以及本批实际依赖的角色组件、
选择题适配器、复用探针包装器、本批脚本/测试和配置。固定真实调用入口
只允许消费这些冻结文件；请求前重新校验，不在生产文件变化后继续执行。

实际请求以 SDK 边界为准记录参数，区分传入值与提供方实际接收值；不把
未发送的 top_p/top_k/seed 写成已经生效。保持相同任务的模型间参数一致，
不为某个模型单独调整提示、推理参数或解析方式。

## 5. 执行顺序、停止规则与恢复

固定顺序：ACT01–03 → CHAIN01–06 → REV01–08 → REP01–03。
每个样本先 `AI_MODEL_4`，再 `AI_MODEL_1`；一个模型的当前样本链完成或
失败后才开始另一个。每个 slot 有唯一 ID，在发出请求前持久化 started
状态、预算与输入哈希；收到结果后归档原始响应、提供方标识和实际参数。

语义错误或格式错误：保留该例失败；链中尚不能执行的下游标为
`skipped_by_upstream_failure`，继续其他预注册样本，不补跑本例。

网络/API 错误、超时、未知模型路由、源码/协议漂移、配额或实验脚本错误：
停止继续付费请求，保留现场并报告原因，不擅自换配置继续。已知 Gemini
请求名与返回名差异应在协议中提前披露；不据此宣称已验证真实模型身份。

请求已开始但无已归档结果的 slot 标为 `started_no_result`，不重发，不
当作成功，也不免费返还额度。脚本重新进入批次时先检查该状态；只能做
离线汇总或报告阻塞，不自动重启。已有原始产物不覆盖。

## 6. 标注与通过条件

逐例阅读原始输出，按冻结标签和来源证据标注，不只看模型 valid 字段。
记录标注者、`annotator_type`、判定及具体文本依据。agent 可以提供初评，
但必须标为 agent；不能冒称人工确认。真实人类尚未确认时，人工质量
验收状态保留为 pending，不自动进入完整故事。

分别报告：

- ACT：格式/角色边界、具体选择、等待依据、无理由重复及角色声音。
- CHAIN：核心是否合法、生成是否保真、评审是否正确、实际请求数。
- REV：合法样本误拒绝与非法样本漏检，原始裁决和 canonical 分别取证。
- REP：重复判断，以及建议/融合的合法性、关联性和实际新变化。
- 实验完整性：全部预定条目、跳过/失败/未决、请求数、重试、耗时与身份。

通过门槛：有效预注册样本均完成；ACT 无关键边界违规或无依据重提已满足
条件，CHAIN 六例均形成合法保真且获准的结果，REV 八例均与预期一致，
REP 判断与冻结标签一致，REP01 的建议/融合合法且关联当前问题。每项
都有实际标注依据；不能靠全拒绝、更多旁白或更多干预通过。

实验或人工验收未完成时，不写 `overall_pass=true`；报告分列工程执行、
agent 初评与人工确认状态。94 次是预算上限，少于 94 次并不自动意味着
不完整，须按每例允许的分支逐项核对。

任何关键边界未过，本批如实判失败；修复应另立版本和新批次，不覆盖本批。
不能用这 20 个样本证明完整故事可完成或稳定改善；完整故事协议待本批
结果审阅后另行决定。
