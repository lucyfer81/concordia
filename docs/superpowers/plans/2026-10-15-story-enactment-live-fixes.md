# 真实模型演绎问题修复方案

日期：2026-10-15。依据：`run_results/story_enactment/` 下
`gemini-3.8-flash-high` 与 `gpt-6-luna` 两次老宅遗嘱运行。
用户已授权制定方案并派发 subagent 实施。保留工作区已有修改，不提交、
覆盖既有运行结果或调用付费模型；源码范围为 contrib 与本示例。

## 设计决定

1. **角色自主权优先。** GM 同时接收全体角色姓名、底线、秘密和世界约束。
   角色只通过自己的对白作主动选择；GM 不代替认罪、承诺、披露私隐、
   交付物证或签字。GM 所知不等于在场角色所知；请求、指控、意图不等于
   已发生事实，角色说谎不自动改变世界真相。
2. **旁白只有一个事实来源。** 模型仍返回两个字符串字段，维持现有接口；
   校验两轨的事实一致性后，由程序使用原始对白与 stage_directions 构造
   正式事件，防止仅在某一轨新增事件。原始对白和换行不改写。
3. **提交前语义复核。** 使用 InteractiveDocument 单独发起一次结构化复核，
   检查玩家越权、未经角色披露的秘密、底线、既有事实、白名单和双轨一致性。
   复核是模型判断，不能宣称为数学保证；发现违规或输出无效即明确 error，
   不重写、不追加无限补问、不广播、不提交该步、不消费导演指令。
   每轮增加一次模型请求，经过原有预算和重试包装器；预算不足仍走裁决前
   停止路径，保留上一完整 checkpoint。
4. **不强行保证好结局。** 保留陈母“绝不承认碰过遗嘱”的底线，将矛盾的
   “主动坦白”结局改为无需认罪的协商路径。节拍必须依据公开、已发生事件
   判断；具体允许结局必须已经成立，不能仅因提及核验或有意向就完成。
   保留 beat_timeout，不增加强制认罪、强制散场或无限延长机制。
   同类修复覆盖面试、婚礼验收配置，保留角色底线，并同步其匹配末拍。
5. **改善节奏不牺牲立场。** 对白提示要求回应最近的新信息，结合自己的目标
   和表达风格，不重复众人相同的程序表态；仅有标点或措辞变化不算推进。
   张力评分区分大声争吵与新风险，收尾不得凭空宣称所有人已同意。
6. **证据可追溯。** 每次运行保存脱敏完整配置、相关源码/提示快照和摘要；
   恢复时保留历史快照并记录当前执行版本。StoryTurn 携带本轮导演指令
   生成/执行/失效状态，checkpoint 继续作为唯一提交边界。

## 分工与接口

| 负责人 | 修改范围 | 交付 |
|---|---|---|
| resolution subagent | story_resolution.py/test、story_dramaturgic.py、story_prefabs_test.py | 单源正式事件、严格结构化复核、GM 参数接线、生命周期拒绝测试 |
| narrative subagent | run.py、story_config.py/test、story_isolation_test.py、story_enactment_test.py、testing_stubs.py | 全角色底线/秘密参数、结局与节拍条件、对白约束、确定性集成及预算回归 |
| director subagent | drama_director.py/test、director_note.py/test | 可观察的张力量表、保守完成提示、约束导演建议、每轮指令诊断及保存恢复测试 |
| 主代理 | provenance.py/test、运行接线整合、README/设计同步、最终检查 | 源码与配置归档、跨模块测试、复审与交付 |

跨模块 GM 参数统一为 `player_names`、`character_constraints`
（姓名到 hard_constraint 的字典）、`world_constraints`、`immutable_facts`；
原有 world_constraints 内保留私隐与允许环境事件。复核只读这些上下文，
不能将其广播。新增可选参数须向后兼容旧 prefab 配置。

## 验收与测试

- 将 Luna T7 的代认罪/代泄密/代集体同意，以及 Gemini T18 的签字仅出现在
  旁白等问题转成确定性负例；拒绝后无角色传播、无已提交记录和指令消费。
- 合法自我披露、请求核验、他人的未证实指控、纯环境事件为正例；同一事件
  的原始对白及旁白同时到达角色观察和 FDX 导出。
- GM 提示含全体角色底线；玩家提示不包含他人私隐、未来节拍或结局指导。
- 仅计划封存/离开不能完成末拍；已经发生的允许结局可以完成；超时原因保留。
- 预算覆盖新增复核调用，覆盖复核阶段耗尽、复核无效、API 错误；恢复不重复
  提交或消费，诊断字段旧 checkpoint 缺失时仍能加载。
- 归档不含 API key，首次调用前已有快照；恢复追加版本且不篡改旧快照。
- 使用 MockModel 或确定性 stub；针对修改运行 pytest，然后分别运行
  `pytest concordia`、`pytest examples`、`pylint --errors-only concordia`、
  `pyrefly check concordia`，以及修改文件的 pyink/isort 与 diff 检查。
- 历史依赖问题单独记录，不能宣称全绿。真实模型复测为后续独立验证：先做
  tension_observe 对照，再做 director；不将自动化测试视为剧情质量已通过。
